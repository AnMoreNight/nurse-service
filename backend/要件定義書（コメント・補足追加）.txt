要件定義書
________________
1. システム概要
本システムは、訪問看護・訪問介護事業所向けの スケジュール管理・シフト管理・訪問実績管理 を行うクラウド型 SaaS である。
複数の事業所（Company）が同一システム上で運用されるため、マルチテナント構成を採用し、
各事業所のデータは Row Level Security（RLS） により完全に分離する。
主要目的は以下の通り:
1. スタッフ別の訪問スケジュールを効率的に管理する（カレンダーUI）
2. 訪問予定・シフトをドラッグ＆ドロップで直感的に編集できる
3. 訪問実績（訪問記録）をデジタル化し、スマホでも入力できる
4. 将来的な 100 事業所 / 1,000 ユーザーの利用を想定し、高い拡張性を持つ
________________


2. ユーザーと権限
1. System Admin
SaaS プラットフォーム全体を管理する。
具体的には、以下を行う:
* Company（事業所）作成・削除
* Company Admin アカウントの作成
* 全テナントのログやリソース状況の確認
System Admin は全テナントのデータにアクセス可能だが、操作は限定的にする想定
2. Company Admin
事業所単位の管理者。
主な操作は以下 :
* スタッフアカウント作成・招待
* スタッフ情報編集
* シフト作成（勤務形態の割当）
* 訪問予定の管理
* 会社設定（色設定など）
Company Admin は 自社テナントのデータのみ閲覧・操作可能
3. User
現場の看護師・リハ職・介護職員を想定。
主な操作は以下 :
* 自身のスケジュール確認
* 訪問実績の入力
* 患者情報の閲覧（権限に応じて制限）(今後追加)
________________


3. 機能要件
A. スケジュール・訪問管理（核心機能）
1. 訪問予定の作成
作成時に入力する情報は以下 : 
* 患者名
* 訪問日時（開始・終了）
* 担当スタッフ（複数設定可）
* 訪問場所（患者住所）
* 種別（看護 / リハ / 介護 / 緊急 など）
* メモ
* ステータス（REGULAR / EMERGENCY / CANCEL といったラベル）
2. 繰り返し予定（Recurrence）
一般的な訪問看護の特性を踏まえ、以下のルールに対応 : 
* 毎週 〇曜日（例：毎週火曜日）
* 隔週（例：2週おき）
* 毎月 同日（例：毎月 10 日）
* 毎月 第〇曜日（例：第 2 金曜）(今後追加)
変更するときは Scope を指定する。(今後追加)
* 今回のみ変更
* これ以降すべて変更
* 全件変更
（例：祝日対応のため、来週だけ時間変更など）

3. ステータス管理
各訪問予定には状態を持つ。
   * REGULAR（通常訪問）
   * EMERGENCY（緊急訪問）
   * CANCEL（キャンセル）
Company Admin は事業所独自のカラー設定を行える。
________________


B. スタッフ管理
1. 基本情報
以下を保持。
   * 名前
   * 職種（看護師、理学療法士、作業療法士、ヘルパーなど）
   * 表示カラー（タイムラインでの識別）
   * アバター画像
   * 入職日・退職日
   * 契約形態（常勤 / 非常勤等）
2. スタッフステータス管理(今後追加)
   * 在籍中 / 退職
   * 履歴保持（例えば、訪問実績と紐づくため）
________________


C. シフト管理
対応すべき勤務形態
   * 日勤
   * 夜勤（2交代制）
   * 夜勤 1・夜勤 2（3交代制）
   * 休日
   * 夜勤明け休み(今後追加)
   * 特別勤務（研修・会議など）(今後追加)
________________


D. マルチテナント・セキュリティ
1. データ分離（最重要要件）
   * すべてのデータは companyId（tenant_id）で紐づく
   * すべての API / クエリは RLS によって tenant_id 以外のデータにアクセス不可
2. パフォーマンス
将来 100 テナント、1,000 ユーザーを想定し以下を実施
   * tenant_id ベースでのパーティショニング（Supabase / Postgres）
   * 必須カラムのインデックス最適化
   * 大量スケジュール表示のため FullCalendar と Virtual Scroll を併用
3. Noisy Neighbor 対策
   * テナントごとに接続負荷を分散
   * クエリの実行コスト制限
   * 重い集計処理はバッチ処理または非同期関数で対応予定
________________


4. 画面一覧（画面定義）
1. 認証系
   * ログイン画面
   * パスワードリセット
   * 初回招待リンクでの登録導線
2. System Admin 向け
   * Company 一覧
   * Company 詳細
   * Company 作成
   * Company Admin の作成
3. Company Admin 向け
   * スタッフ一覧
   * スタッフ登録 / 編集
   * 患者一覧
   * 患者登録 / 編集
   * スケジュール管理（Resource Timeline ・ FullCalendar）
   * シフト管理画面
   * 設定（色設定など）
4. Staff 向け
   * 自分のスケジュール一覧
   * 訪問記録入力画面
   * 訪問記録履歴
   * 自分のプロフィール(今後追加)
________________


5. ワークフロー（業務フロー）
1. 事業所開始まで
   1. System Admin が Company を作成
   2. Company Admin を登録
   3. Company Admin がスタッフを招待
   4. Staff が招待メールからユーザー登録
   5. 運用開始
2. スケジュール作成フロー
   1. Company Admin が患者情報を登録
   2. スタッフを割り当てる
   3. 訪問予定を作成
   4. スケジュールがカレンダーに反映
   5. 必要に応じて予定変更（ドラッグ＆ドロップ）
   6. Staff に通知
3. 訪問当日のフロー
   1. Staff が訪問
   2. 訪問記録を入力（スマホ対応）
   3. Company Admin が記録内容を確認
   4. 最終確定
6. 非機能要件セキュリティ
   * RLS による完全なデータ隔離
   * JWT 認証
   * 管理者権限の厳格化
パフォーマンス
   * 100 テナント / 1,000 ユーザー規模で運用可能
   * カレンダー表示を高速化（キャッシュ、Lazy Load）
可用性
   * 24/365 稼働想定
   * 定期メンテナンスは夜間

ーーー
補足
デモでこだわった機能は、以下の１～１３の機能となります。１３はマストではありません。
＜１＞
予定をドラッグ＆ドロップで移動でき、保存の際は繰り返し予定の枠を変更した場合、「この予定」と「以降すべて」が選べる。
  



＜２＞
スタッフの表示の順番をドラッグ＆ドロップで入れ替えできる。
  

＜３＞
スタッフが複数選択できる。
  

＜４＞
住所を登録するとgooglemapへ移動できる。
  

________________


＜５＞
ステータスは、通常訪問（看護）、通常訪問（リハ）、緊急訪問、その他、キャンセルの５つで、それぞれ違う色で表示される。
  

＜６＞
繰り返しは「毎週」「毎月」「毎年」で、「毎月」は、第〇曜日を選択できる。（日付で指定はなくても可）
  

________________




＜７＞
訪問詳細のデータをコピー（患者名と住所のみ）して、新規の予定を作成できる。
  





＜８＞
シフト管理は、「出勤」「公休」「夜間待機１」「夜間待機２」「夜間待機１（休）」「夜間待機２（休）」から選択できる。
  

＜９＞
シフト管理では、公休を曜日で選択でき、自動反映できる。その後、手動で変更も可能。
  

＜１０＞
患者名でスケジュール検索ができる。
  

＜１１＞
管理者がユーザーと管理者を追加・権限変更できる。
  

＜１２＞
スケジュールとシフトがCSVで出力できる。
  

________________


＜１３＞
ステータスが追加できる。
